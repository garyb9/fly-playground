## 1. Goal

A small browser **playground** in which a simplified simulation of the male
*Drosophila* connectome (Janelia FlyEM / Google Research **MaleCNS v1.0**) drives
a 3D fly flying freely through a bounded world. Sensory stimulus is injected into
the network; motor activity is decoded out of it to fly the body. The brain is
drawn as a point cloud that pulses with activity. There is ambient audio and a
few objects to fly around.

Explicitly **not**: a living fly, biophysical accuracy, or a "consciousness
upload". The **wiring is real**; the neuron equations, sensory encodings, and
motor decodings are engineered models. Same honesty caveat the `fly-escape` and
NeuroCraft authors state.

### Core concept (decided)

**The brain drives the fly.** One system: world sensors → sensory neurons → LIF
network step → motor/descending readouts → 6DOF flight.

### Non-goals / YAGNI

- No EM imagery, no volumetric rendering, no neuron *meshes* (skeletons/meshes
  are a possible later cosmetic layer for *selected* neurons only).
- No biophysical channels (Hodgkin–Huxley), no plasticity/learning.
- No multiplayer, no persistence, no backend. Fully static.
- No Next.js / SSR / routing.
- Swarms of flies are out of scope (one fly).

## 2. Approach (decided: "A — core + expandable shell")

Preprocess the connectome into a **tiered binary**: a small hand-picked
**behavioural core** (~1–3k neurons: looming detectors, giant-fiber escape
circuit, descending neurons, wing/steering motor neurons) plus the rest of the
brain **sorted by connectivity importance**. A **neuron-count slider** sets a
cutoff `N`; the sim integrates neurons `[0, N)` with the core always included.

The sim runs at a **fixed 200 Hz in a Web Worker**, decoupled from render
framerate, so the slider can go all the way to the full ~166k neurons — the sim
tick rate drops (documented as "heavy") but nothing blocks and the fly stays
alive because the core is always integrated.

Rejected alternatives:
- **B** (full graph always, buffered, slider only gates rendering) — not
  real-time, slider doesn't change behaviour.
- **C** (pure region explorer, no fixed core) — fly frequently does nothing;
  poor default. Its idea survives as the optional region/class filter.

## 4. Data pipeline (offline, `pipeline/`, Python)

`fetch → filter → tier → core_circuit → emit_bin`. Downloads `body-annotations`
(~13 MB) + `connectome-weights` (~1.1 GB) + neurotransmitter feathers from the
public GCS bucket; prunes edges to ~15–25 M; ranks neurons by weighted degree;
groups by neuropil/class; bakes an excitatory/inhibitory sign per neuron;
hand-curates the core circuit and the sensory-input / motor-readout neuron lists;
emits compact little-endian binaries. Full detail, column assumptions, and the
core-circuit type list: [`data-pipeline.md`](data-pipeline.md).

Asset shipping: small files committed; large `graph.bin` distributed as a
release/static-host artifact and cached in IndexedDB by `manifest.version`. A
seeded ~500-neuron **synthetic fixture** is committed so app + CI need no
download.

## 5. Simulation core (`crates/fly-sim`, Rust → WASM)

**Leaky integrate-and-fire**, discrete fixed 5 ms step (200 Hz). Per active
neuron: `v ← leak·v + input + bias`; fire on `v ≥ v_th` when not refractory,
reset, propagate `w·sign` to postsynaptic `input_next` (double-buffered);
decay refractory. Seeded PRNG for noise/spontaneous drive → **deterministic**
(golden-trace tested). Excitatory/inhibitory is a **baked per-neuron sign bit**
from neurotransmitter predictions (Dale's principle assumed; an acknowledged
approximation).

WASM API: `new`, `set_active_count`, `inject(role, value)`, `step(ticks)`,
`readout(role) -> f32`, `activity_snapshot() -> Float32Array`. Full equations,
parameters, weight scaling, storage formats, slider semantics:
[`neuron-model.md`](neuron-model.md).

## 6. Body, world, sensing (main thread, `src/`)

### 6a. Fly body & flight — `body/`
6DOF rigid body. Readouts → wrench: symmetric wing amplitude → forward thrust +
lift (tuned so `wing ≈ hover_level` cancels gravity → **hovering is the neutral
state**); wing asymmetry → roll + yaw; `thrust` / `yaw_torque` → direct trims;
`escape` over threshold → one impulsive takeoff burst + brief control lockout
(giant-fiber jump). Linear + angular drag for stability; low-freq noise on
readouts for lifelike jitter. Sphere-vs-AABB collision; hard hit → `proximity`
startle spike.

### 6b. World — `world/`
Bounded volume with soft push-back walls. `scene.config.ts` defines: ground
plane, a few primitive objects (block / sphere / torus to weave through), 2–3
point lights that double as the light stimulus. Adding an object = one array
entry.

### 6c. Sensing — `sensing/` (decided: proximity + looming + light)
Per frame, pose + world → smoothed scalars → `inject()`:
- **proximity** — inverse distance to nearest surface (few raycasts).
- **looming** — angular-size growth rate of the nearest forward object; the
  escape trigger (matches LC looming-neuron encoding).
- **light L / light R** — per-eye dot against each light → left/right gradient
  for phototactic steering.
- **wind** — optional slow vector field → bilateral antennal channel.

## 7. Brain visualization — `brainviz/`
`THREE.Points`, one vertex per loaded neuron (positions from `neurons.bin`,
scaled so the brain ≈ 1 unit), per-vertex colour from the activity snapshot each
frame (dark → hot); core neurons larger. Core-circuit edges as faint
`LineSegments` so the loom → GF → motor pathway lights up. Two camera modes:
**follow** (chase the fly; brain in a **docked corner panel by default**, or
co-located with the fly via config flag) and **brain** (orbit / free-fly through
the connectome; fly shown as a marker). Toggle key.

## 8. Audio — `audio/`
Web Audio. Ambient bed (looped sample or 2–3 detuned oscillators through a
lowpass) + reactive one-shots: soft blip on escape, wingbeat hum whose pitch
tracks wing amplitude. Master mute + volume in the HUD. Starts muted until first
user gesture.

## 9. HUD — `ui/`
DOM overlay: neuron-count slider (log scale `core_count … N`, shows live
`sim_hz`), region/class filter checkboxes (**stretch**), camera toggle, audio
controls, readout meters (thrust / yaw / escape) and sensory meters
(proximity / looming / light L·R) so stimulus → brain → motion is visible.

**Build:** `wasm-pack build crates/fly-sim --target web`; `vite` bundles the
shell; `vite build` → static `dist/`. Deploys to any static host; a
`SharedArrayBuffer` fast path needs COOP/COEP headers, with a `postMessage`
fallback that always works.

## 11. Testing strategy (TDD throughout)

- **Rust:** LIF leak/threshold/refractory; CSR traversal; 2-neuron exc/inh pair;
  golden-trace determinism (`tests/golden_trace.rs`).
- **TS unit (vitest):** binary parsers round-trip vs. fixture; readout → force
  mapping (known readouts → expected wrench); sensing math (looming rate, light
  L/R gradient) with hand-computed cases; worker-protocol encode/decode; ring
  buffer torn-read handling.
- **Integration (headless):** boot sim with fixture, inject a looming ramp,
  assert `escape` readout crosses threshold within a bounded tick count — the one
  end-to-end "the brain reacts" test.
- **Pipeline (`pipeline/tests/`):** CSR invariants (monotonic offsets, in-range
  targets), core occupies `[0, core_count)`, every role list non-empty, non-core
  importance non-increasing, positions finite, binary round-trip.
- **CI:** `cargo test` + `wasm-pack build` + `vitest` + `tsc --noEmit` +
  `vite build` on the fixture.
- **Manual checklist (in `docs/`):** fly hovers stably; slider changes `sim_hz`;
  object in path triggers escape; light gradient induces turning.

## 12. Risks / open questions (resolve during implementation)

1. **Soma positions** — confirm `body-annotations` carries usable coordinates;
   fallbacks: `neuprint-python` `somaLocation`, SWC roots, synapse centroid.
   Only a hard blocker if all four fail.
2. **Core circuit body IDs** — mapping published looming / GF / DN / motor type
   names to MaleCNS `bodyId`s needs real neuPrint spelunking. The whole
   "brain drives behaviour" story depends on it — budget time; never silently
   drop a role.
3. **`SharedArrayBuffer` / COOP-COEP** — host may not allow the headers;
   `postMessage` fallback must exist from day one (both behind `SimBridge`).
4. **Full-slider performance** — 166k neurons may drop the sim to 10–20 Hz.
   Acceptable and documented; must confirm it doesn't crash the tab (cap N, or
   switch `activity` snapshot to per-group means at high N).
5. **Asset hosting / size** — large `graph.bin` distribution unresolved until a
   host is chosen; synthetic fixture keeps everything working meanwhile.
6. **Weight normalisation `W_NORM`** — needs empirical tuning so the core
   circuit actually spikes at sensible rates; expect an iteration loop against
   the manual checklist.

## 13. Rough build order (for the implementation plan)

1. Repo scaffold: Vite + TS + empty Rust crate + CI + committed synthetic
   fixture + binary format encoders/decoders (TS & Rust) against the fixture.
2. `fly-sim` LIF + CSR + determinism tests, driven by the fixture.
3. `SimBridge` (worker + ring buffer + postMessage fallback), `brainviz` point
   cloud rendering the fixture with live activity colour.
4. `body/` 6DOF flight from mock readouts; `world/` + `scene.config.ts`.
5. `sensing/` scalars; wire sensing → `inject` → sim → `readout` → body; the
   end-to-end looming→escape integration test.
6. `ui/` slider + meters + camera toggle; `audio/`.
7. Real pipeline: `fetch/filter/tier/core_circuit/emit_bin`, produce real
   assets, tune `W_NORM`, run the manual checklist.
8. Asset hosting + IndexedDB cache; deploy target + COOP/COEP or fallback.
9. Stretch: region/class filter UI; selected-neuron skeletons.
